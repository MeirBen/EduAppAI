Active run

What do run statuses mean?

Completed means the workflow finished, not that every check passed. Cancelled, rate-limited, call-limit and failed runs keep their partial results. Cancelling cannot stop a call already in progress, which may still cost credits. There are at most three retries per call for HTTP 429, within Max calls. Other failures are not retried. Only one run can be active.

New run

Pick cases, check the plan, then confirm. Nothing runs before that.

New here? A practical workflow
  1. Start with one relevant case, one repeat and the Hebrew judge off.
  2. Open the report in History, read the content and answers, and record your review.
  3. Enable the judge when investigating language quality; it adds calls.
  4. Label a baseline, change one prompt or model setting, and rerun the same selection before comparing.

Where do these cases come from?

Maintained examples in cases.json, not family content. Add one for a real gap or regression and restart the dashboard. Tasks use generated defaults, or the maximum count when a case asks for it.

Run plan

A fallback model is configured, so the returned model can differ. Check it in reports before comparing models.

Each repeat creates a fresh template and task. Max calls includes retry attempts; set it above the base plan to leave retry headroom. It caps calls, not money. Set an OpenRouter key limit for a spending cap.

Wait after each call before sending the next, including judge calls. Default: 5 seconds; 0 disables the pause. Paid providers can still return 429. Increase the pause if needed. Temporary 429 errors allow up to three retries within Max calls, using the provider's Retry-After or increasing waits of about 5, 10 and 20 seconds. A provider wait over five minutes stops the run instead of retrying early.

How the judge works
  1. Calibration checks known examples for missed errors and false alarms, once per run.
  2. Content review proofreads each successful template/task pair.
  3. You decide. The same model can miss its own mistakes; no findings is not proof of good Hebrew.

How to read a report
Contract passed
The response met the app's structure and validation rules.
Automatic checks
Case checks such as question, choice and passage counts; not every instruction.
Judge calibration
Known-example detection. If it fails or is unfinished, trust findings less.
Hebrew findings
Advisory. No completed review means no language evidence, not zero errors.
Human review
0 unusable, 1 needs edits, 2 ready. Leave unchecked dimensions unreviewed.
Cost / latency
Cost can be incomplete; unknown is not free. Latency excludes timeouts.

Reports include generated answer keys; keep them private. Saving a review changes only your local scores and notes.

Compare

Deltas are candidate minus baseline. They describe changes; there is no winner.

How to make a useful comparison
  1. Change one model or prompt setting between the baseline and the candidate.
  2. Keep cases, repeats and judge setup identical; otherwise runs are incomparable.
  3. Read compatibility first. Hebrew and human deltas need matching reviewed results.
  4. A positive delta only means higher; inspect examples before concluding.
